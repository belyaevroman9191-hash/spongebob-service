# SPONGEBOB SERVICE — перенос на Vercel

## Что изменено
- Оставлены исходные HTML/CSS/JS, изображения и музыка.
- `/api/*` перенесены в Vercel Serverless Function (`api/[...path].js`).
- Данные админки, настройки, сессии, посетители и события хранятся в PostgreSQL через Neon, а не в локальном `data/db.json`.
- `/admin` и `/admin/` переписываются на `admin.html`.
- Cookies сессии выставляются с `Secure` для HTTPS.

## Обязательная настройка перед запуском
1. Импортируйте папку проекта в Vercel или загрузите обновлённый ZIP в свой Git-репозиторий.
2. В Vercel откройте **Storage / Marketplace** и подключите Neon PostgreSQL (или создайте Neon DB отдельно).
3. В **Settings → Environment Variables** добавьте `DATABASE_URL` — pooled connection string базы данных с SSL.
4. Включите переменную для Production (и Preview, если нужно), затем сделайте **Redeploy**.
5. Откройте `https://ВАШ-ДОМЕН/api/config`: должен вернуться JSON с настройками сайта.
6. Откройте `https://ВАШ-ДОМЕН/admin`, проверьте вход, аналитику и сохранение настройки.

Таблица `spongebob_app_state` и начальные настройки создаются автоматически при первом API-запросе. Существующий `data/db.json` не используется как постоянная база на Vercel. Если в нём есть нужные настройки, перенесите их через админку после запуска или отдельно импортируйте в PostgreSQL.

## Важно
- Без `DATABASE_URL` API вернёт ошибку 500 — это ожидаемо, пока база не подключена.
- Секреты не добавляйте в `vercel.json` или Git; храните их в Environment Variables.
- Эта версия использует JSON-документ в одной строке PostgreSQL, чтобы сохранить совместимость со старой моделью данных. При очень большом количестве одновременных посещений лучше перейти на отдельные таблицы и атомарные операции.
- После деплоя проверьте все разделы и функции. ZIP сам по себе не меняет уже опубликованный сайт: его нужно загрузить в репозиторий и выполнить новый deployment.
